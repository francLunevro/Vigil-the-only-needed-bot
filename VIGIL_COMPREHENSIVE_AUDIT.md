# Vigil comprehensive audit

2026-11-04 · Vigil 1.1.0 · Working tree based on 12bf4436551ba1c33178b938bb246d369a2b2df8

## 1. Executive Summary

Vigil has enough moderation, ticketing, automation and operational tooling for a small self-hosted pilot after its authorization and dependency fixes. **Two confirmed cross-guild authorization failures block shared deployment.** One exposed a private staff note through a mixed-case URL. The other deleted a foreign note through a canonical URL for an authorized guild. Both were reproduced with synthetic records, a temporary database and a mock dashboard on loopback. A reachable HTTP body parser also falls within a high-severity advisory range.

Scope includes relevant tracked and untracked working-tree code, tests and deployment files. References are to the audited working tree. This was a targeted deep review and inventory. It did not trace every branch of all 163 direct HTTP registrations or every feature handler. Live Discord behavior, production performance, browser accessibility, deployed proxy policy and historical secrets were not verified. Existing databases, uploads, chat dumps, bundled skills and generated trees were excluded except for dependency metadata and relevant installed library code. No source changes or dependency installs were performed.

## 3. Security Assessment

### SEC-01 · High · Confirmed route-casing tenant bypass

src/dashboard-backend/parts/02-auth.js:221–226 extracts a guild with a case-sensitive regex before routing. src/dashboard-backend/index.js:36 leaves Express routing case-insensitive. Part 05:216 relies on that early check plus requireAuth. A fixture session granted guild A received 403 for the canonical guild B notes URL and 200 containing a synthetic note when the API/server path casing changed. A valid dashboard session, reachable app and cached target guild are prerequisites for the demonstrated path. Other handlers relying on the same guard can reach ungranted-guild operations, subject to their own checks and bot permissions. Owner-only routes have an independent guard.

Attach authorization to router-matched guild parameters and test all methods, capitalization, encoded identifiers, empty grants and anonymous access. **Confidence: high.**

### SEC-02 · High · Cross-guild object authorization in notes and ticket panels

src/dashboard-backend/parts/05-moderation.js:249–255 resolves the guild from the URL, then calls removeNote with only the object ID. src/staffNotes.js:33–44 edits and deletes by ID. A DELETE under authorized guild A returned 200 and removed a synthetic guild B record. src/commands/note.js:59 and :77 use the same ID-only helpers, exposing a similar path to users allowed to invoke those subcommands. The caller needs the foreign note ID. This threatens private staff-record integrity independently of SEC-01. The same object-ownership defect is visible in ticket panels: src/dashboard-backend/parts/09-tickets.js:193–220 verifies the URL guild but passes an unscoped panel ID to updatePanel or deletePanel. src/tickets.js:65–91 resolves and mutates by panel ID. The type and clone routes at part 09:293–332 similarly operate on globally resolved objects. An actor with a foreign panel/type ID can reach those mutations from an authorized guild. The ticket variant is source-confirmed and was not exercised over HTTP.

Make guild ID mandatory in helpers and in atomic select/update/delete predicates. Return an identical miss for absent or foreign records. For tickets, require both the panel guild and type parent to match in the same storage operation, including clone, send, reorder and counter changes. Attribute writes to the real actor and audit sibling object routes. **Confidence: high.**

### SEC-03 · High · Reachable compressed-body parser advisory

package-lock.json:1397 locks body-parser 2.3.0. src/dashboard-backend/index.js:55–65 mounts parsers globally before authentication and rate limiting. The advisory applies to malformed compressed request bodies with trailing bytes. A reachable origin accepting compressed requests can lose both HTTP and the bot on process failure. Advisory applicability and parser reachability were verified without sending a crash payload.

Resolve body-parser 2.4.0 or later, gate parsing by route and ingress, and reject compression where unused. **Confidence: high for version and reachable parser.** [Advisory](https://github.com/advisories/GHSA-27r3-jxmh-p828)

### SEC-04 · Medium · SSE keeps expired authority

Part 10 at src/dashboard-backend/parts/10-insights.js:314–336 checks the session once and snapshots guild grants. Its broadcast loop keeps using that Set until disconnect. src/events/messages.js:154 and :205 emit message-related events. An already-connected client can receive events after session or guild grant revocation. Expiry checks on later HTTP requests do not cover that response.

Index streams by session, close on revocation or expiry, refresh grants, and bound connection count, lifetime and buffered bytes. **Confidence: high from source.**

### SEC-05 · Medium · Avatar URL causes a host-side fetch

Part 03 at src/dashboard-backend/parts/03-dash-admin.js:195–202 and src/commands/config.js:210 pass the URL to setAvatar. Installed discord.js src/util/DataResolver.js:83–98 and :133–139 fetch and buffer the image. The dashboard route is owner-gated and the Discord command has runtime policy. Such a caller can cause requests to destinations reachable from the process. Response exfiltration was not demonstrated.

Prefer bounded image uploads. For remote input enforce explicit destination and redirect rules, byte/time limits and DNS checks. **Confidence: high in fetch path, deployment-dependent impact.**

### SEC-06 · Medium · Proxy trust makes throttling topology-dependent

src/dashboard-backend/index.js:36–51 trusts private/local peers by default and makes TRUST_PROXY=1 unconditional. Part 02:69–105 keys buckets by req.ip. core.js:354–358 separately considers raw forwarded proto when setting Secure. A reachable origin behind an overly trusted peer or an ingress that preserves attacker forwarding headers can expose spoofable rate-limit identity.

Trust only the exact proxy paths, normalize forwarded headers, restrict origin ingress and use account-aware login limits. **Confidence: high in configuration behavior.**

### SEC-07 · Medium · Upload metadata and storage limits

src/dashboard-backend/core.js:580–597 trusts client MIME metadata and bounds individual files. Part 03:130–134 requires owner access for uploads and serves the resulting directory publicly. Repeated uploads can consume disk and mislabeled content can persist. A script execution chain was not verified.

Decode and re-encode allowlisted formats, set response MIME and nosniff, and enforce quotas and cleanup. **Confidence: high.**

### SEC-08 · Medium · Coarse dashboard staff authority

Part 02:101–134 accepts a shared password or Discord ID plus a Vigil-issued token. It has no OAuth exchange. Part 02:168–204 makes password sessions installation owners and models other users with per-guild grants. Individual actions that rely only on guild scope inherit all authority for that guild. Shared credentials collapse attribution and increase compromise blast radius.

Add named identities and explicit action capabilities, with a break-glass owner path. If adopting OAuth, verify identity through the exchange and map membership and actions deliberately. **Confidence: high.**

### SEC-09 · Low · Multer advisory dependency

package-lock.json:3012 pins Multer 2.4.0. The advisory requires a pending asynchronous fileFilter during request teardown. Vigil's core.js:590 filter calls back synchronously and part 03:130 requires an owner. The exact trigger was not demonstrated. Upgrade to 2.5.0 or later and test aborted uploads. **Confidence: high for version, low for application trigger.** [Advisory](https://github.com/advisories/GHSA-q7qp-rjg7-q26m)

### SEC-10 · Low · Logging and attribution gaps

src/dashboard-backend/index.js:81–89 accepts a caller request ID and logs path, IP and user agent. src/logError.js:61–66 and :100 output INFO stacks. Part 05:245 writes a generic dashboard author for staff notes. Routine use increases personal metadata and noise, and the generic actor hinders investigations. Generate and bound correlation IDs, redact metadata, define retention, suppress routine stacks and persist the actual actor. **Confidence: high.**

### SEC-11 · Informational · Other advisory entries and reviewed controls

npm also flagged qs 6.16.0 and minimatch 10.2.6 at package-lock.json:3437 and :2975. The former requires a specific comma-format stringify sink. The latter is in the lint chain. No relevant public trigger was established. ESLint, config-array and eslint-utils carry inherited entries. Update within a compatible toolchain. **Confidence: high for version evidence.** [qs advisory](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw) · [minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249)

Session/token digests, idle and absolute TTLs, HttpOnly/Strict cookies, source-map blocking, bound SQL values and CSP are substantive controls. Import tests reject SQL-shaped column keys. Part 11:198 and :206 use a strict backup filename pattern. No other CSRF, XSS, SQL/shell injection, traversal, unsafe redirect or CORS credential exposure was established in the traced paths. Legacy HTML and data-fn dispatch remain separate review surfaces. A filename-only scan for several credential markers returned no candidates in included text files. It did not examine history, entropy or local private data.

Message history, transcript content, appeals, staff notes and audit data have different privacy lifetimes. src/db.js:1219–1254 prunes some usage, activity and ticket-message rows. Explicitly inventory transcript text, exported data and backup retention. Define guild offboarding and member-deletion policy, with role-limited export access and independently recoverable encrypted copies.

### Reproduction notes

Create a fresh temporary DATA_DIR and UPLOADS_DIR and mount createDashboard on loopback with mock guild caches. Issue a dashboard token to a fixture account, grant it only guild A and log in. Insert a private staff note under guild B. Canonical GET for guild B returned 403 without the fixture text. Mixed-case API/Server GET returned 200 with the fixture text. Canonical DELETE using the guild A URL and the guild B note ID returned 200 and the synthetic row count dropped from one to zero. Keep these as separate regressions so that fixing route casing alone cannot mask the object defect.

## 5. Code Quality

- **Policy duplication:** Slash picker defaults, runtime grants, prefix checks, component checks and REST checks describe related authority separately. Make shared action policies explicit and allow adapters to supply identities. Keep installation-owner authority distinct from Discord guild authority.
- **Large modules:** db.js and tickets.js each exceed 1,200 lines and deploy.js exceeds 1,900. Extract around domain operations after defining guild keys, transaction boundaries and failure semantics. A rewrite is unnecessary for the first release gates.
- **Catalog drift:** commands/info.js:39 advertises 35+ commands. commands/help.js, deploy.js, registry.js and part 10:309 have independent catalog data. Generate help, status and dashboard displays from the registry and deployment schema. Cover platform visibility separately from runtime rules.
- **Failure semantics:** Distinguish successful Discord action, persisted audit event and optional notification. Blanket catches and separate SQL/REST calls make partial success hard to explain. Apply typed validation and error envelopes first to moderation, tickets and import.
- **Frontend duplication:** Freeze or retire the vanilla fallback only after React parity and build packaging are tested. Until then, maintain separate legacy escaping, CSP and data-fn coverage.

## 6. Performance & Scalability

No workload or production benchmark was run. The table describes plausible architectural constraints, with no capacity guarantee.

| Guilds | Assessment | Validation needed |
|---|---|---|
| 10 | Plausible for modest workloads on a single host with durable storage. Event and ticket volume matter more than guild count. | Typical traffic plus busy backup, slow SSE and restart. |
| 100 | Potentially viable, pending synchronous SQL and timer/API profiling. | Loop lag, query and REST latency, queue depth, high-traffic guild and max transcript. |
| 1,000 | Single-process blast radius and timer ownership need attention before a reliable claim. | Shard and job partitioning, bounded concurrency, failure isolation and reconciliation. |
| 10,000 | Unsupported by current evidence. | Separate web/gateway failure domains, storage topology and shard failure rehearsals. |

The first measurement targets are session renewals (core.js:196), per-client SSE writes without backpressure handling (part 10:336), full-member fetches and serial guild refreshes (serverStats.js:125, :224), and transcript fetches (tickets.js:761). Batch session writes, cache query results with explicit invalidation, profile query plans and pre-serialize SSE payloads. Track worker lag and Discord REST budgets before adding concurrency. At scheduledPosts.js:141–164 a successful remote send precedes completion persistence, allowing replay on process failure. At db.js:1102–1112 the backup path does a synchronous WAL checkpoint and copies the primary file without checking checkpoint completion. A busy reader can leave newer changes in WAL. Use SQLite online backup and test the resulting restore under write load.

## 7. Dashboard UI/UX

The source review covered React navigation, common components, media rules and the legacy fallback. Visual fidelity, measured contrast, interaction latency and actual mobile/assistive behavior remain unassessed.

- **Navigation:** Organize Shell and the palette around daily operations, guild settings and host operations. Show active guild, available permissions and connection status consistently. Turn a zero-grant dashboard into an actionable setup state.
- **Configuration:** Provide section-level save, dirty-state protection, field errors, retry and last editor. Prevent stale fetches or drafts from crossing a guild switch. Use separate confirmation for destructive actions.
- **Work queues:** Put open tickets and moderation cases in filterable queues with stable links, ownership, age and last action. Preserve table semantics and usable overflow on small screens.
- **Accessibility:** Toasts use aria-live and styles include reduced-motion handling. The palette markup in CommandPalette.jsx:78–98 needs keyboard/focus and dialog semantics verification. Test focus return, error announcement, touch targets and contrast on actual devices.
- **Presentation:** Normalize typography, spacing and state tokens in web/src/styles.css. Use motion for feedback on save or view transition, with equivalent reduced-motion behavior. Preserve forms during SSE reconnection and expose stale data explicitly.

Dyno's case-oriented moderation logs, Carl-bot's modular navigation and ProBot's guided dashboard module setup are documented workflow benchmarks. Their visual quality and performance were not independently measured. ## 8. Discord Interaction Experience

Vigil has shared embed helpers, ephemeral feedback and separate ticket, poll, voice, moderation and log-search components. For a coherent interaction system, acknowledge slow requests before REST or transcript I/O. Use short ephemeral validation feedback with a remedy. Give staff actions a consistent result, subject and case reference. Use text alongside symbols and suppress mentions by default. Bind components to actor, guild, channel and object where appropriate. Expired buttons should point to the current workflow. Test slow API calls, double clicks and failed notifications after successful moderation. Generate public and staff help views from authoritative command metadata.

## 11. Premium Product Readiness

Vigil's most defensible early market is small self-hosters who want their own ticket, moderation and case data. The technical buying blockers are tenant isolation, dependable recovery, named staff delegation, reproducible installation, dashboard workflow parity and a supported update path. Publish release notes and a concise first-install checklist. Prioritize the operator's ability to diagnose or recover from failure over expanding command count.

LICENSE sections 2.1 and 2.5 permit commercial operation and paid installation, hosting and support under stated conditions. Sections 2.3 and 4 constrain charging for copies and redistribution. Selling paid copies and offering paid services are different models under these terms. Establish the applicable distribution rights before pricing or packaging the offering.
